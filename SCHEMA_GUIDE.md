# Schema Guide

Schemas are the canonical source for cross-language contracts shared by the FastAPI backend (`services/api`), TypeScript clients (`packages/types`), and module documentation.

**Related:** [API_CONTRACTS.md](API_CONTRACTS.md) · [docs/README.md](docs/README.md) · [DOMAIN_GLOSSARY.md](DOMAIN_GLOSSARY.md)

## Rules

- Use JSON Schema Draft 2020-12.
- Include `$id`, `title`, `type`, and `required`.
- Use explicit enums for controlled scientific vocabularies.
- Add compatible fields; avoid renaming or changing semantics.
- Every schema must have at least one example in `examples/`.

## Naming

```txt
schemas/<domain>/<entity>.schema.json
```

Example:

```txt
schemas/eln/experiment.schema.json
```

## Required Common Fields

- `id`
- `organization_id`
- `created_at`
- `updated_at`

## Keeping contracts in sync (mechanically enforced)

The Pydantic models in `services/api/helixos/eln/schemas.py` are the implementation. Three artifacts must agree with them, and CI fails if they drift:

| Artifact | How it is checked |
| --- | --- |
| `schemas/**/*.schema.json` | `tests/test_contracts.py`: property names, required set (responses always serialize every field), enums and nullability match the model; every schema has a valid `examples/<domain>/<entity>.json`; live API responses validate against the schemas |
| `packages/types/src/eln.generated.ts` | Generated by `python scripts/generate_ts_types.py` (run from `services/api`); CI runs it with `--check` |
| `examples/**` | Must validate against the schema and parse with the model |

When you change an ELN model: update the matching schema and example, regenerate the TypeScript types, and commit all of them. A new schema file must be added to `CONTRACTS` in `tests/test_contracts.py`. Request models (`*Create`, `*Update`, `*Request`) make defaulted fields optional in TypeScript; all other models are emitted with every field required. Types outside the ELN module (auth, AI, MCP, audit) are still hand-written in `packages/types/src/index.ts`.
