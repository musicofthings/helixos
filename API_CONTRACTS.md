# API Contracts

HelixOS exposes versioned REST APIs under `/api/v1`.

**Context:** [docs/README.md](docs/README.md) · [SYSTEM_ARCHITECTURE.md](SYSTEM_ARCHITECTURE.md) · [docs/modules/](docs/modules/) (per-domain behavior and audit notes)

## Standards

- JSON request and response bodies.
- Bearer authentication. Hosted deployments verify OIDC-issued JWTs (signature via the provider's JWKS, issuer, audience, expiry); local development also accepts documented demo tokens.
- Tenant isolation by `organization_id`.
- OpenAPI generated by FastAPI.
- Errors use a stable envelope.

## Error Envelope

```json
{
  "error": {
    "code": "not_found",
    "message": "Experiment not found",
    "details": {}
  }
}
```

### Error Codes

| Status | Code | Meaning |
| --- | --- | --- |
| `401` | `unauthorized` | Missing, expired, or unverifiable bearer token |
| `403` | `forbidden` | Actor cannot access the requested `organization_id`, or their role does not allow the action |
| `403` | `account_disabled` | The signed-in user has been disabled by an operator |
| `503` | `auth_unavailable` | The identity provider's keys could not be fetched; retry shortly (do not sign the user out) |
| `409` | `last_admin` | The change would leave an organization without an admin |
| `409` | `member_exists` | That person is already a member |
| `404` | `not_found` | Resource missing, or outside the actor's tenant |
| `409` | `version_locked` | Signed versions are immutable — commit a new version |
| `409` | `plate_full` | Experiment already holds 96 samples |
| `409` | `well_occupied` | Another sample already occupies that well |
| `422` | `invalid_well` | `well_position` is not a valid `A1`–`H12` coordinate |
| `422` | `invalid_update` | A `PATCH` sent an explicit `null` for a non-nullable field |

`PATCH` bodies omit fields to leave them unchanged. Sending an explicit `null` clears a
nullable field (`description`, `well_position`); sending `null` for a non-nullable field
(a project's `name`/`status`, a sample's `name`/`sample_type`/`status`/`metadata`) is
rejected with `422 invalid_update` rather than overwriting the record.

## Authentication

Protected `/api/v1` endpoints require an `Authorization: Bearer <token>` header.

**OIDC (hosted).** Set `HELIX_OIDC_ISSUER` and `HELIX_OIDC_AUDIENCE`; the API accepts RS/ES/PS/EdDSA-signed JWTs from that provider whose `aud` matches, and rejects everything else (including `alg: none` and HMAC tokens). The token must carry `sub`, and, for invite matching and email-addressed workspace shares, `email` plus `email_verified: true`. Users are created on first sign-in; their memberships and roles live in HelixOS ([docs/modules/auth.md](docs/modules/auth.md)). The actor's `subject` in audit events and shares is HelixOS's own user id (`usr_…`), not the provider's `sub`.

**Local starter tokens** (development; opt-in in staging; never in production):

- `demo-admin-token`: access to `org_demo` and `org_qc`.
- `org-demo-token`: access to `org_demo`.

Any token that is neither a permitted demo token nor a valid OIDC JWT is rejected with `401`. For local development against a mock identity provider that issues unsigned JWTs, `HELIX_ALLOW_UNVERIFIED_JWT=1` additionally accepts unsigned payloads (`sub` + `organization_ids` claims). Hosted environments (`HELIX_ENV=staging|production`) ignore that flag and refuse to start with it set; demo tokens are opt-in in staging and never accepted in production ([docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)).

The authenticated actor determines tenant visibility; clients cannot widen access by passing arbitrary `organization_id` query parameters or request fields.

## ELN Data Model

HelixOS organizes lab work as a hierarchy, each level tenant-scoped by `organization_id`:

```txt
Workspace (category + optional subcategory)   e.g. Next Generation Sequencing · RNA
  └─ Project                  e.g. Reporter plasmid program
       └─ Experiment          the "repo" — tracks a HEAD version
            ├─ ExperimentVersion  immutable snapshot ("commit"); new edits create a new version
            └─ Sample          up to 96 per experiment, optional A1–H12 plate well
                 └─ Dataset    DNA/RNA/protein sequence, measurement, or file
```

Experiments are versioned like source control: `POST /experiments/{id}/versions` creates a
new immutable `ExperimentVersion` with a `parent_version_id` and commit `message`, and moves
the experiment's `head_version_id` forward. Signed versions are read-only.

Workspaces carry a `category` and an optional free-string `subcategory` refining it. Categories
with suggested subcategories:

- `next_gen_sequencing` → DNA, RNA, Protein
- `digital_pathology` → Cells, Tissues
- `programmable_bio` → Single-cell experiments, PerturbGen, Protein-protein interaction studies (extensible)

`molecular_biology`, `biochemistry`, and `microbiology` carry no subcategory. Suggested
subcategory values are advisory only; the API accepts any string so labs can extend the lists.

`DELETE` on a workspace, project, or experiment cascades to everything nested beneath it in a
single transaction and returns `204`. Each deletion records an audit event
(`eln.workspace_deleted` / `eln.project_deleted` / `eln.experiment_deleted`). Workspace delete
also removes collaborator grants and invite links.

### Workspace collaboration

Collaborator grants and invite links with enforced roles:

- **Access levels:** org members are implicit **owners** (full access, including delete workspace and share management). Share grants add **viewer** (read subtree) or **editor** (create/update/delete under the workspace, but not the workspace itself or share admin).
- **Listing:** `GET /workspaces` returns org workspaces **plus** workspaces shared with the actor (shared-with-me).
- **Grants:** `POST /workspaces/{id}/shares` with `{ "subject", "role" }` (subject must be a known demo user id or an email). `PATCH …/shares/{id}` updates role.
- **Invites:** `POST /workspaces/{id}/invites` with `{ "role", "expires_in_hours?", "max_uses?" }` (default 168h). The capability `token` is returned **only on create**; list/collaboration responses set `token` to `null`. Accept via `POST /workspace-invites/{token}/accept` (no prior org membership required).

Audit events: `eln.workspace_share_granted`, `eln.workspace_share_updated`, `eln.workspace_share_revoked`, `eln.workspace_invite_created`, `eln.workspace_invite_revoked`, `eln.workspace_invite_accepted`.

## Example Version Status Update

Applied to a specific experiment version via
`PATCH /api/v1/experiments/{experiment_id}/versions/{version_id}`.

```json
{
  "status": "in_review"
}
```

Allowed transitions: `draft` ↔ `in_review` → `signed`. Signed versions are immutable
(`409 version_locked`); amend by committing a new version instead.
